WFM Watch — DB2 SQL Reference (by menu)

How queries reach DB2

All production monitoring uses JDBC via db2DirectService → DB2Connector.java (direct connection to each client DB2).

Runtime placeholders (values from Admin → Config unless noted):

  • {days} — engine.batchQueryDays (default 7) or engine.dbMonitorBatchDays (default 2) on DB Monitor
  • {stalePendingDbMins} — threshold.stalePendingDbMins (default 30)
  • {maxBatchDetailRows} — engine.maxBatchDetailRows (default 500)
  • {punchLookbackDays} — engine.punchLookbackDays (default 2)
  • {weekEndDate} — integer yyyyMMdd (user-selected or computed previous week)
  • {distListId} — store group from STD_QUEUE_JOB.PARAM_3 (Payroll Monitor)
  • {jobType} — sanitized alphanumeric job type from UI drill-down
  • {planTypeFilter} — see Batch Status Details below

Caller: BatchStatusDetails · Service: db2-direct-service.ts → getBatchStatusDetails()

{planTypeFilter} is built at runtime:

  • Non-empty plan type: RTRIM(LTRIM(CHAR(bs.PLAN_TYPE))) = '{planType}' (single quotes escaped)
  • Empty / blank group: (bs.PLAN_TYPE IS NULL OR RTRIM(LTRIM(CHAR(bs.PLAN_TYPE))) = '')

{jobType} is sanitized to alphanumeric + underscore only.
